## 3. 架构合理性检查

| 检查项 | 结论 |
|---|---|
| 技术选型 | 评审时 Java 21、Spring Boot 3、MyBatis-Plus、MySQL 8、Redis、Sa-Token、Vue 3 均未变；评审通过后按用户决定改为 JDK 17（Eclipse Temurin）、Spring Boot 4.1，线程模型见第二阶段 5.8 |
| 服务边界 | 模块化单体，19 个模块对应 20 个包（M14 拆为 `ai`、`safety`） |
| 模块职责 | 每张表只由归属模块写入；修正后 42 张表的归属与写入接口一致 |
| 调用关系 | 修正后依赖图**没有循环**，依赖图与依赖表逐条一致（脚本检查） |
| 例外 | 仅 M18、M19 允许跨模块只读 SQL，已在第二阶段 4.3 记录 |

修正后的关键依赖：

- `help` 依赖 `account`：注册时 M01 发布"学员已注册"事件，M17 订阅后记录协议同意。
- `learning`、`practice`、`interview` 依赖 `account`：通过 M01 的公开接口记录活跃。
- `feedback` 依赖 `account`：展示提交学员的昵称。

## 4. 数据库与接口一致性检查

| 检查项 | 结果 |
|---|---|
| `schema.sql` 与数据库设计文档 | 42 张表的字段名、类型、可空、注释、索引、CHECK 约束逐项一致 |
| 接口字段与数据库字段 | 接口共使用 225 个字段名，99 个与数据库字段同名；其余 126 个是计算结果、请求控制参数或 Redis 中的短期数据，已在 API 设计 8.2 节逐个列出 |
| 枚举取值 | 接口中的状态、题型、模式、角色等取值与数据库 CHECK 约束一致 |
| 字段长度 | 接口的长度限制不超过数据库字段长度 |
| 缺失 | 没有接口需要而数据库缺少的数据。看板留存原来只存比率，无法按周、月合并，已改为存人数（P08） |
| 冗余 | 部分数据库字段只在服务端使用、不对外返回，属于内部需要，不是冗余：`exam_session.full_score`、`practice_session.planned_question_ids`、`interview_session.config_snapshot`、`interview_report.failure_reason`、`sys_user.password_changed_at`、`course_open_log` 的路线和阶段字段 |
